## 좌우 공통 명령

| 상태 | 상전류 부호 | 목표 RPM | RUNNING |
|---|---|---|---|
| D 가속 | + | +4000 | 1 |
| D 회생 | - | 0 | 1 |
| R 가속 | - | -4000 | 1 |
| D/R 브레이크 + 스로틀 | 해당 기어 구동 부호 | 해당 기어 ±4000 | 1 |
| R 브레이크 + 스로틀 해제 | 0 | 0 | 허용 상태이면 1 (무토크) |
| N/P/미허용 | 0 | 0 | 0 |

좌측 ID 0x0C01EFD0, 우측 ID 0x0C01F0D0에 동일 부호 규칙을 사용한다.
RUNNING은 토크 모드 Byte4=0x01이며 목표 RPM 0을 속도제어 모드와 혼동하지 않는다.

`longitudinal_compute`는 기어 적용 전 양수=구동, 음수=제동의 합산 전류를 만든다.
`directional_current`는 D에서 부호를 보존하고 R에서는 구동만 음수로 바꾼다.
R 제동 요구는 0이다. 따라서 `abs(total_torque)`로 회생이 가속으로 바뀌지 않는다.
스로틀이 양수이면 브레이크와 무관하게 구동한다. 회생 스위치 ON/OFF 모두 같다.
스로틀은 기존 ADC 보정을 거친 0%를 사용한다(ADC 자체가 0이라는 뜻이 아니다).
0%가 10회 연속(100Hz에서 100ms) 확인되어야 회생을 재허용하고, 작은 양수라도
즉시 회생을 해제한다. 새로운 페달 진폭 데드존 대신 시간 기반 재진입 필터를 사용한다.
CAN 송신 직전에도 유효 스로틀 0%를 확인하여 남아 있는 음수 회생 명령을 차단한다.
가속 램프의 구동 판정에서도 브레이크 조건을 제거하여 D/R 동시 입력에서도
기존 0.5초 상승 제한과 전력 제한이 작동한다. 회생 시 가속 램프 이력은 리셋된다.
브레이크만으로 고착 스로틀의 구동을 차단하지 않는 정책이므로, 활성화 전
경기 규정 적합성과 기계식 제동/긴급 차단을 별도 검증해야 한다.
`motor_direction_command`는 최종 CAN 명령을 결정한다.
양쪽 컨트롤러 피드백이 fresh이고 두 RPM 모두 양수일 때만
D 회생 명령을 허용한다. 하나라도 정지/역회전/미수신이면 양쪽 회생을 차단한다.
이는 방향 차단 조건이며 저속 감쇠·히스테리시스·ABS 구현은 아니다.

## 이번 변경으로 활성화되지 않는 것

- `BRAKE_SENSOR_INSTALLED=false`, `REGEN_HARDWARE_VALIDATED=false` 유지.
- 회생 계산/송신 모두 pack_data_valid를 요구한다. 이것만으로 BMS 충전 허용전류,
  셀 과전압, 온도 제한까지 검증된 것은 아니다.
- GPIO33 HIGH=밟음인 3.3V 호환 디지털 신호 확인이 필요하다.
- 기존 회생 상한은 일반 모드 합계 20A, 효율 모드 합계 30A이다.
  TV OFF 기준 각각 모터당 10A/15A이며 이번 작업에서 올리지 않았다.
- 좌우 크로스코어 명령 스냅샷 PR은 별도다. 이번 변경은 전체 공유상태의 원자성을
  해결했다고 주장하지 않는다.
- 센서/충전 조건 확인, 저속 감쇠와 투입 변화율 검증 후에만 활성화한다.
  소프트웨어 단위 테스트는 실제 제동 토크·회수 에너지 검증을 대신하지 않는다.
