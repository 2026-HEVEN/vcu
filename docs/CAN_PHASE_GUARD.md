# EZkontrol 피드백 끊김 대응 — 판정 완화 + 명령 위상 가드

대상 브랜치: `dev` (M2 스쿼시 `7090c7d` 이후)
근거 자료: 노션 「CAN 통신 단절 진단 및 대책」 11장 (2026-09-24)

## 1. 문제

버스 오류가 0인 상태에서도 EZkontrol 컨트롤러가 피드백 프레임을 스스로 멈춘다.
기존 VCU는 FB1 **그리고** FB2가 250 ms 안에 와야 토크를 허용했다. 한 파트만
750 ms 넘게 빠져도 링크를 끊었다. `REQUIRE_BOTH_MOTOR_CONTROLLERS` 때문에
한쪽 컨트롤러의 한 파트만 끊겨도 **양쪽 모터 토크가 차단**되고, 복구할 때는
1 s 램프를 거친다. 주행 중이면 1~2 s 동안 출력이 빠진다.

## 2. 벤치 측정 (2026-09-24, PCAN으로 VCU 흉내, RUN=1 0 A, HV 30 V)

| 현상 | 조건 | 결과 |
|---|---|---|
| 위상 창 | 명령이 FB1 송신 1.1~2.5 ms 전에 도착 | FB2 30~80% 누락, FB1 일부 누락. L·R 모두, 펌웨어 1.0.23·1.0.24 동일 |
| 위상 무관 몰림 | 위상 20 ms 고정, 10분 | FB2 공백 >250 ms가 L 20회, R 19회(최대 700 ms). FB1 공백 >250 ms 0회, **두 파트 동시 두절 0회**. 기존 판정이면 토크 차단 39회, 새 판정이면 0회 |
| 실제 VCU (정확히 50 ms) | 정차, 3분 | FB1 단독 600~995 ms 5회. 위상이 창을 지날 때 L 폭주, 재프로브 3회 |

- 실제 VCU와 컨트롤러 클럭 차이는 약 100 ppm이다. 위상이 약 500 s에 한 바퀴 돌면서
  창을 지날 때마다 10 s 이상 폭주한다.
- 두 현상 모두 **FB1과 FB2가 따로따로** 빠진다. 한 파트가 끊긴 동안 다른 파트는 계속 들어온다.

## 3. 변경

### 3.1 피드백 판정 (`controller_feedback_fresh` / `controller_feedback_lost`)
- **토크 허용:** FB1 또는 FB2 중 하나가 250 ms 안에 왔고, FB1 ≤ 1.5 s, FB2 ≤ 7 s.
- **링크 무효화:** 두 파트가 모두 750 ms 넘게 없을 때, 또는 FB1이 1.5 s를 넘거나 FB2가 7 s를 넘을 때.
- 결과적으로 FB1 기반 상전류 감시는 최대 1.5 s, FB2 기반 오류·온도는 최대 7 s까지
  늦을 수 있다. FB2가 최대 6.1 s 끊기는 것은 09-21에 확인된 값이다.
- 한도는 `fixed_config::runtime::CONTROLLER_FB1_MAX_AGE_MS`, `CONTROLLER_FB2_MAX_AGE_MS`에 있다.
- **엄격 판정은 따로 유지한다.** FB2의 오류·온도 값을 읽고 결정하는 곳(결함 재무장
  `rearm_conditions_ok`, 컴포넌트 시험 `left_ok/right_ok`)은 `controller_feedback_both_recent`
  (FB1 **그리고** FB2가 250 ms 이내)를 쓴다. 오래된 "오류 없음"으로 재무장하지 않게 하려는 것이다.

### 3.2 명령 위상 가드 (`cmd_phase_step`)
- 좌우 명령은 지금처럼 **한 스냅샷에서 연달아** 보낸다(M2 원칙 유지). 한 쌍의
  송신 시각만 주기 안에서 옮긴다.
- 매 주기 다음 송신 시각 기준으로 각 컨트롤러의 위상(송신에서 다음 FB1까지)을 계산한다.
  FB1 수신 시각은 5 ms RX 폴링을 거치므로 0~5 ms 늦게 측정된다.
- 측정 위상이 안전 대역 `[12, 46] ms` 밖으로 **3주기 연속** 나가면, 두 위상이 목표 대역
  `[18, 40] ms`에 들어가는 가장 작은 이동량(±25 ms 이내)만큼 다음 송신을 옮긴다.
  목표 대역에 둘 다 들어가지 않으면 안전 대역을 쓴다. 가능한 모든 위상 조합에서 해가
  있다는 것을 native 테스트로 전수 확인했다.
- 이동은 `[CAN] command phase shift ...`로 시리얼에 남는다. 클럭 차이로 수 분에 한 번 정도 나야 정상이다.
- 이동 직후 한 주기만 간격이 25~75 ms가 된다. 컨트롤러 명령 타임아웃(250 ms 이상)보다 충분히 짧다.

## 4. 검증 상태

- native 테스트 `test_can_link_policy` 16개 통과, 전체 native 통과, `esp32dev` 빌드 통과.
- **실차 미검증.** 필요한 확인:
  1. 실제 VCU + PCAN 수신 30분: 링크 무효화 0회, 위상 이동 로그 정상
  2. 주행 시험: 부하 상태에서도 위상 창이 같은지, 한 파트 끊김 중 토크가 유지되는지

## 5. 남은 항목

- 버스 오류 순간 송신 중이던 명령 프레임이 1.2 s 늦게 나간 사례(라이프 84→109).
  `twai_clear_transmit_queue()`는 이미 송신 중인 프레임을 멈추지 못한다.
  명령 프레임에 single-shot 송신을 쓰는 방안은 재전송이 사라지는 동작 변경이라 별도로 판단한다.
