# 2026-09-28 오류 복구 단순화 및 남은 구동 조건 점검

대상: `C:/HEVEN/HEVEN-vcu` dev, 기준 커밋 `0ac99c4` 이후 이번 작업본. 보드 업로드 전 코드 점검 결과다.

## 이번에 변경한 동작

- 컨트롤러별 Part II 오류가 한 번 들어오면 즉시 해당 측의 오류 대기 상태를 세우고 양쪽 명령을 차단한다. 실제 송신은 모터 CAN 송신 주기를 따른다.
- 오류가 있었던 측의 새로운 정상 Part II를 연속2회 받아야 그 측의 대기를 해제한다. 왼쪽 정상 프레임으로 오른쪽 오류를 해제할 수 없다.
- 오류→정상→오류가 반복되면 정상 횟수를 다시0으로 한다. 두 프레임 오류 확정 단계, 별도 영구 래치, 수동 재무장 함수, 복구 전용 온도/전류/페달/통신 중복 검사는 제거했다.
- 링크 무효화는 부분 복구 횟수만 초기화한다. 오류 대기를 지우지 않으므로 재연결 뒤 새 정상2회가 필요하다. 양쪽 링크 등 공통 조건은 계속 별도로 적용한다.
- 복구 뒤 처음 실제 비영점 출력이 허용되는 시점부터250ms 전류 상승 램프를 적용한다. 최초 오류와 발생측 기록은 제어에서 분리해 보존한다.
- Part I 상전류 절댓값1000A 초과로 VCU 래치를 걸던 경로를 삭제했다. 수동 모터시험의 같은 측정값 검사도 제거했다.
- 일반 추정 전력 제한은 기존 false 유지. Paddock의 추정8kW·컨트롤러 버스전류 합200A·BMS 전류150A 제한은0으로 비활성화했다. 관련 계산/선택 기능은 향후 계측 기반 개발을 위해 남아 있지만 현재 프로파일에서는 적용되지 않는다.
- 컨트롤러가 보내는 오류 비트 자체는 계속 구동 차단 대상으로 취급한다. 측정 전압/전류값이 낮거나 높다는 이유로 VCU가 별도 오류를 생성하는 경로와 구분한다.

구현: `src/logic/safety_logic.cpp::fault_recovery_update`, `src/core/can_bus.cpp::update_fault_feedback`, `src/modules/fixed_config.h`, `src/modules/realcar_calibration.h`.

## 자동으로 복구되는 전체 구동 차단

| 원인 | 차단 기준 | 복구 조건/조작 |
|---|---|---|
| 컨트롤러 오류 | Part II error1/2/3 중 하나라도0이 아님 | 오류 발생측 정상2회. 공통 조건 정상이라면 페달 유지 재개,250ms 램프. N/수동 해제 불필요 |
| 스로틀 입력 무효 | ADC raw<200 단일 제어 표본에서 무효, throttle=0 및 Halt | 주행 이력이 있으면 유효 입력·handshake·heartbeat 정상 후 페달 유지 복귀. 최초 부팅은 별도 해제 조건 유지 |
| 수신 오래됨 | 한 컨트롤러의 Part I·II 모두250ms 초과 또는 Part I>1500ms/Part II>7000ms | 수신 정상·링크 준비 후 자동. 둘 다750ms 초과면 링크 무효화/재연결 경로 |
| 송신 실패 | 한쪽 모터 명령 enqueue 실패 연속3회 | 해당 링크 무효화 후 재연결. 실제 수신 ACK 확인과 enqueue 성공은 구분 |
| TWAI bus-off | CAN 드라이버 bus-off | 드라이버 복구·재시작·handshake 후 자동 |
| 제어 루프 정지 | heartbeat가200ms 이상 오래됨 | 정상 루프 복귀 시 자동. 펌웨어가 실제로 멈춰 복귀하지 않으면 외부 재시작이 필요할 수 있음 |
| 명령 오래됨/미게시 | snapshot 나이>100ms 또는seq=0 | 새 유효 명령 게시 후 자동 |
| 비정상 명령 | 좌/우 최종 명령 NaN/Inf | 유한한 명령 복귀 후 자동. 센서 측정값 보호와 다른 명령 형식 검증 |
| 컨트롤러 speed_mode | 토크모드가 아닌 피드백 | 토크모드 피드백 복귀 후 자동 |
| 온도 제한 | 컨트롤러75~85℃, 모터100~120℃ 선형 감산, 상한에서 양쪽0A | 온도 하강에 따라 자동 복귀. 온도 제한은 이번 전압/전류 정리와 별개로 유지 |
| Paddock 정보 무효 | 온도<-30℃ 또는 BMS 정보 무효(PADDOCK_REQUIRE_PACK_DATA=true) | 정보 복구 또는 정상 수신된 Paddock OFF 요청. BMS는5초 미수신시 무효. 일반 모드 전체 구동 차단 조건은 아님 |

위의 자동 복구는 다른 차단 조건이 동시에 남아 있지 않을 때 적용된다. 예를 들어 오류 비트가 정상으로 돌아와도 기어 방향 미무장 상태는 그대로다.

## 전체 구동을 막지 않는 제한/기능 조건

- 일반 전류 상승 램프는0초. CAN 재연결250ms와 오류 복구250ms 램프는 유지한다.
- 모터별 목표 상전류 상한500A, Efficiency100A 및 명령 타입 범위는 유지한다. 실측 상전류 초과 차단과 다르다.
- Paddock 속도별 목표 상전류는 정지400A/모터→80km/h에서50A/모터. 계측 전류/전력 제한만0으로 껐으며 이 명령 상한은 유지한다.
- TV는 스위치·게인·IMU·차속 유효·최소속도 조건 미충족시 비활성화되고 기본50:50으로 돌아간다. 활성 TV의 하중/마찰원 상한은 총 가속 요구를 줄일 수 있다.
- 브레이크 입력만으로 가속을 차단하지 않는다. 현재 회생은 페달0%를10회(명목100ms), D기어, 양쪽 전진RPM 임계 통과, Cluster ON, BMS 유효/SOC 조건으로 허용한다. 회생 OFF/BMS 무효는 일반 가속 차단과 다르다.
- Cluster 명령200ms 미수신은 TV/회생 요청을 해제한다. 이미 활성화된 Paddock은 유지한다.
- SYNC_ARM/RUN/CANCEL 시험은 별도 수동 명령으로만 시작하며 조건 상실시 중단한다. 정상 구동 복구를 영구 잠그는 래치는 없다.
- VCU의 shutdown_ok 입력은 현재 코드에서 true 고정이다. 물리 차단 회로 상태를 별도 GPIO로 읽는 보호로 오해하면 안 된다.

## 로그 해석

`0x1C07C0D0` 차단 bit4, `0x1C08C0D0` Byte7 bit0은 현재 오류/정상2회 대기다. Byte7 bit1(옛 rearmReady)은0, Byte0~6 최초 오류는 복구 후 보존된다. 최초 오류 바이트가 남았다는 사실만으로 현재 차단이라고 판단하지 않는다. 과거 로그는 당시 펌웨어의 래치 의미로 해석한다.

`FAULT_REARM` 명령은 호환 안내만 출력하고 상태를 바꾸지 않는다. 복구를 위해 입력할 필요가 없다.
